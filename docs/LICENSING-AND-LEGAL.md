# Licensing and legal decisions — owner review required

No application LICENSE existed at audit time. No new permission grant has been selected automatically. A public GitHub repository does not by itself grant general permission to reuse its content; see [Choose a License: no license](https://choosealicense.com/no-permission/).

| Material | Current evidence | Action before publication/reuse |
|---|---|---|
| Application source | Personal project; no explicit license | Confirm contributors/ownership and choose terms. Apache-2.0 is a candidate if permissive reuse with explicit patent terms is desired; MIT is simpler if that is the owner's intent. Neither has been applied. |
| Curriculum | Imported from user-supplied AI Automation Course Curriculum PDF | Confirm authorship or redistribution permission. Choose separate content terms; do not silently include it in an application license. |
| Learner code and README | Read from selected GitHub repositories | Remain the learner's material. No public portfolio publication or license grant is inferred. |
| Evidence snapshots | May contain source, notes and private repository contents | Local private data; exclude from releases and logs. Set retention/deletion policy for any future hosted service. |
| Generated logo | Generated with a user-supplied visual reference, documented in design-system/LOGO.md | Confirm reference rights and suitability. Generation does not prove exclusive rights or trademark clearance. |
| Poppins, Lucide, dependencies | Third-party packages | Preserve upstream license notices; inventory in NOTICE.md. Review transitive notices before distribution. |
| Social card | Repository-native SVG composition, plus raster export | Brand use still requires owner approval; no external ratings, affiliation or certification claims. |

Recommended split: application software license; separate curriculum/content license; no blanket license for user evidence; separate brand usage policy. Obtain the owner's decisions before adding a LICENSE file. This document is an implementation checklist, not a legal opinion.

## Privacy policy draft inputs

Public mode provides read-only curriculum pages and no app analytics/cookies. The host may receive IP addresses and request logs. The operator must name the actual operator/contact, hosting provider, purposes, retention, user rights/contact process and applicable jurisdiction before calling this a complete privacy policy. No invented organization or email address is supplied.

Local workspace: SQLite holds repository binding, commit, source, brief, README, checks and history. Browser storage holds self-review and optional ChatGPT conversation URLs per repository/project. GitHub tokens remain backend environment/in-memory session. Requests go to GitHub on explicit sync/login; Coach opens ChatGPT only on user action. ChatGPT review is separate and does not automatically change progress. Reset clears SQLite evidence and in-memory OAuth, not browser-profile localStorage or externally hosted data.

## Terms draft inputs

Describe the educational purpose, no mastery/employment guarantee, user responsibility for repository permissions and secrets, third-party service availability/costs, prohibition on uploading others' confidential data, support scope, rights in source/curriculum/brands, and any lawful limits of liability. Do not offer certification, paid services or a public hosted workspace that is not implemented. Operator identity/jurisdiction and final legal review remain required.
